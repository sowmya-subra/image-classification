Project write-up

Building a 99%+ Accuracy MNIST Digit Classifier

A walkthrough of how this convolutional neural network was designed, trained, and evaluated on the MNIST handwritten digit dataset: what worked, what didn't, and where it still gets confused.

The problem at hand

MNIST is a dataset of 70,000 handwritten digits divided into 60,000 training examples and 10,000 testing examples. Each example is a 28×28 grayscale image where every pixel is an intensity value ranging from 0 (black) to 255 (white), and labeled with the digit (0–9) it represents.

The intention of this website and class project is to train a Convolutional Neural Network (CNN) that classifies these digits with greater than 99% accuracy. To accomplish this, we need to understand why the CNN makes mistakes, and ship it behind a live web page so anyone can upload their own 28×28 grid and get a prediction.

Preprocessing

Before training the model, every image was normalized from its raw 0–255 pixel range down to 0–1 (divided by 255), and reshaped from (28, 28) to (28, 28, 1) to give it an explicit single-channel dimension, which is what Keras's Conv2D layers expect. This is also what the CSV upload pipeline on the classify page does to the uploaded file before it reaches the model. It will detect whether the values are already 0–1 or if they are still raw (0–255), and normalize accordingly. Additionally, it will detect and alert the user if the uploaded file is not in the correct format.

Trying four architectures

Rather than committing to one design up front, four architectures were trained and compared. A validation_split=0.2 was used during architecture selection, which means that 20% of the training data was held out for validation while the official MNIST test set remained untouched. The models used the Adam optimizer, sparse categorical cross-entropy loss, and a batch size of 64.

Architecture Structure Test accuracy
1 — Simple 1 convolutional layer (16 filters) + pooling → Dense(32) 98.01%
2 — Larger 3 convolutional layers (64/128/128 filters) + pooling → Dense(128) + Dropout 99.19%
3 — Balanced 3 convolutional layers (32/64/64 filters) + pooling → Dense(64) + dropout 99.25%
4 — Push for 99.5% Similar to Architectures 2&3, with Batch Normalization and 15 training epochs 99.24%

The comparison showed that Architecture 1, with a simple one-convolution-layer, performed noticeably worse than the deeper architectures by at least 1 percentage point. The deeper networks were able to learn more complex visual features by applying multiple convolutional layers sequentially.

Architectures 2, 3, and 4 all performed similarly, with test accuracies around 99.2–99.3%. Adding additional complexity, such as the changes included in Architecture 4, did not produce a meaningful improvement compared to the other deep architectures.

Based on this comparison and analysis among all models, Architecture 3 was selected as the final architecture, with a test accuracy of 99.25% in the architecture comparison: 

Conv2D(32, 3x3) → MaxPool(2x2) → Conv2D(64, 3x3) → MaxPool(2x2) →
Conv2D(64, 3x3) → Flatten → Dense(64) → Dropout(0.5) → Dense(10, softmax)

This architecture contains 93,322 trainable parameters. It also provides enough capacity to learn the visual patterns needed for MNIST classification while remaining relatively small and computationally efficient.

Retraining on the full dataset

After selecting Architecture 3, the model was rebuilt from scratch and retrained using the entire 60,000 image MNIST training set. This time, no validation split was used because the validation set had served its purpose during architecture selection. Using the full training set allowed the final model to learn from all available training examples.

The final model was then evaluated on the official 10,000-image MNIST test set.

Final test accuracy: 99.31%

Note that the final model's 99.31% test accuracy was slightly higher than the 99.25% accuracy Architecture 3 achieved during architecture selection. Because the final model was trained on the full training set rather than only the 80% training portion used during architecture selection, the additional training examples may have contributed to the improvement.

The final test set was kept separate from the training and architecture selection process, which provides an evaluation of the model on previously unseen MNIST images.

What the model gets right — and wrong

Out of 10,000 test images, the final model correctly classified 9,931 and incorrectly classified 69, which is a 0.69% error rate.

Well-classified examples

The correctly classified examples above demonstrate the types of images the model handles well. These digits generally have clear and distinguishable shapes, with strokes and loops that make their identity relatively easy to determine. This is similar to how a person would read them with their own eyes.

Misclassified examples

The misclassified examples above provide insight into where our selected model has difficulty. Several errors involve visually similar digits, such as mistaking 4→9, 6→0, 3→5, 2→1/4/7, and 1→7. These errors are understandable because handwritten digits can vary substantially in shape and style from person-to-person.

For example, a 6 with a particularly large or closed loop can resemble a 0, while a 1 with an additional stroke or serif can resemble a 7. Similarly, variations in people's handwriting of a 2, 4, and 7 can make those digits difficult to decipher.

The errors therefore tend to occur on examples where the visual characteristics of two digits overlap. Some of the misclassified images are also difficult for a person to identify immediately, which shows that the problem is not simply that the network fails on otherwise perfectly clear examples.

The model did not make errors evenly across all possible digit combinations. Instead, many errors occurred between digits with similar visual structures. Examining these mistakes is useful because it shows that the model's remaining errors are concentrated in ambiguous or unusually written examples.

Could this ever hit 100% accuracy?

A perfect score of 100% accuracy is difficult to achieve on handwritten data because the images themselves can be ambiguous. As discussed, people may write the same digit differently, and some individual examples may contain shapes that resemble more than one digit.

The remaining errors therefore reflect both limitations of the model and the inherent ambiguity of some handwritten inputs. Improving the architecture may reduce some errors, but it cannot necessarily eliminate mistakes on every ambiguous image of handwritten data.

What this means for the upload tool

The classifier page on this site uses the same trained CNN to make predictions on uploaded MNIST images. A user uploads a CSV containing the pixel intensities for a 28×28 image. The backend validates the uploaded file and converts the data into the format expected by the CNN before making a prediction.

The CSV parser accepts pixel values represented either as the original 0–255 intensity values or as their normalized 0–1 values. The data is converted to the appropriate format before being passed to the model.

The parser also checks for invalid uploads, including incorrect file dimensions, non-numeric values, invalid file types, and inappropriate pixel values. When an uploaded file fails this validation, the user will receive a specific error message explaining the problem rather than the invalid data being passed to the CNN.

This validation step is important because the CNN assumes that its input has the specific structure of a valid 28×28 grayscale image. The upload pipeline therefore acts as a gatekeeper between the user's CSV file and the trained neural network to ensure only valid files are analyzed by this site.

Lessons learned

Testing four different architectures rather than settling on the first model that performed well ended up being one of the more valuable parts of this project, even though it required additional time upfront.

Architecture 1 was intentionally kept simple to establish a baseline. It used one convolutional layer and a small dense layer and achieved 98.01% accuracy. While this is still a strong result, it was about a full percentage point below the other architectures. This showed that the shallow architecture was not capturing the patterns in the handwritten digits as effectively as the deeper models.

The results from Architectures 2, 3, and 4 were more interesting. We initially expected performance to continue improving as the models became more complex. Architecture 4 was designed specifically to try to push accuracy beyond 99.5%. We added Batch Normalization and increased the number of training epochs. Despite these changes, the model finished at 99.24%. This was very close to the results from Architectures 2 and 3. In fact, all three deeper architectures were within about two tenths of a percentage point of each other.

This suggests that the model reached a point where additional complexity was providing very little improvement. The remaining errors may not simply be a result of limited model capacity. Some digits are difficult to distinguish even visually, which could explain why adding more complexity did not have the impact we expected.

The main takeaway from this comparison was that a more complex model does not always produce better results. Architecture 3 was ultimately selected because its performance was comparable to the more complex models. It was also smaller and more efficient to train. For this project, it offered a better balance between performance and complexity.

With more time, it would be useful to explore changes beyond adding more layers. One option would be adjusting the dropout rate or testing a lower learning rate. Data augmentation could also be used to slightly rotate or shift the training images. Based on our results, these types of changes may have more potential than continuing to increase the size of the network.
